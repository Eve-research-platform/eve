# Eve Cloudflare Relay

This folder is the participant-facing component for the downloadable/self-hosted Eve model.

It has two jobs:

1. serve the static Eve participant application;
2. hold encrypted study/response/recording envelopes temporarily in your Cloudflare R2 bucket.

It does **not** receive the participant decryption key and cannot read research payloads.

## Researcher-friendly setup

In Eve:

1. open the first-run Setup wizard;
2. download `eve-relay-setup.json`;
3. run `deploy-relay.bat` (Windows) or `deploy-relay.sh` (macOS/Linux);
4. sign into Cloudflare when prompted;
5. paste the deployed Worker URL back into Eve;
6. select **Test relay**.

The script installs its bundled Wrangler dependency when needed, then uses Cloudflare Wrangler to create the `eve-relay` R2 bucket, stores the generated owner key as a Worker secret, and deploys the Worker/static participant app.

## What the owner key does

Each study already has its own random administrator capability and participant capability.

The relay owner key adds a deployment-wide boundary so that somebody who discovers your Worker URL cannot create arbitrary studies and consume your R2 storage.

The owner key is sent only by the researcher's local Eve application. It is never placed in participant links.

## Data in R2

R2 contains opaque JSON envelopes and routing metadata:

- published encrypted study versions;
- encrypted responses;
- encrypted recordings while they are waiting for durable handoff;
- controlled-audience invitation hashes.

### Recording retention

When the researcher's Eve successfully copies a recording to approved SharePoint/Google Drive, Eve reads the encrypted file back and verifies its recording/response identity. Only then does it ask the relay to schedule that R2 recording for deletion.

The default grace period is **48 hours** (`EVE_RECORDING_RELAY_GRACE_HOURS`). A Cron Trigger runs hourly and deletes only recordings whose scheduled retention deadline has passed. If durable write/read-back verification or retention scheduling fails, the R2 recording remains in place for the next sync attempt.

Eve also keeps a browser-encrypted local playback cache after successful handoff so the researcher can continue reviewing the recording after the relay copy has gone.

The participant decryption key remains in the URL fragment/browser and is never sent to the relay.

## Participant Panel

The standalone Cloudflare relay does not currently implement Participant Panel join/removal/email operations because those contain participant email addresses and are not zero-access research transport.

Do not use a Panel-signup study with the standalone relay until that operational service is added.

## Recording size

The default relay rejects a single recording request larger than 60 MB. Cloudflare plan/request limits vary, so keep recording limits conservative for the initial downloadable beta. A later relay can move large recordings to direct multipart R2 upload.

## Advanced/manual deployment

```text
npm install
npx wrangler login
npx wrangler r2 bucket create eve-relay
npx wrangler secret put EVE_RELAY_OWNER_KEY
npx wrangler deploy
```

Use the owner key generated by Eve Setup when Wrangler asks for the secret value.
